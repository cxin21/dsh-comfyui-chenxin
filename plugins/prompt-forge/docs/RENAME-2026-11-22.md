# 插件更名：prompt-master → prompt-forge（2026-11-22）

## 决策与理由

用户要求换掉插件名（原 `prompt-master`），经权衡定名 **prompt-forge**：

- 「forge（锻造）」贴合插件本质——意图蓝图 → 扩写 → 成文 → 审核 → 修复的提示词锻造管线；
- 与工具名 `prompt_author` 零字形零语义混淆（此前 `prompt-master` 与 `prompt_author` 只差分隔符，易混）；
- kebab-case，符合插件命名惯例。

改名范围 = **插件名、包名、装配清单、活文档**。工具名 `prompt_author` 系列不变（工具名是
agent 契约表面，历史上从未与插件名绑定，无改名需求）。

## 数据契约迁移（settings namespace）

三个 settings namespace 是**数据契约**，key 从 `prompt-master-*` 换为 `prompt-forge-*`：

| 旧 key | 新 key | 数据形状 | 接线点 |
|---|---|---|---|
| `prompt-master-custom-profiles` | `prompt-forge-custom-profiles` | `{customProfiles: Record<string,string>}` | `src/plugin/index.ts` |
| `prompt-master-profile-overrides` | `prompt-forge-profile-overrides` | `{builtinOverrides: Record<string,{enabled,sort}>}` | `src/pe-framework/profiles/storage-v2.ts` |
| `prompt-master-blueprints` | `prompt-forge-blueprints` | `{blueprints: Record<string,string>}` | `src/tools/prompt-author.ts`（blueprintSettingsScope） |

**迁移机制**：`migrateLegacySettingsSection(ctx, newNs, legacyNsName, sectionKey)`
（storage-v2.ts 导出，三处调用）——注册新 key 后检查：新 key 无数据 && 旧 key 有数据 →
把旧 section 复制过来。幂等（搬过一次新 key 非空即短路）；旧 key 数据只复制不删除；
读取/写入失败静默跳过不阻塞加载（与蓝图落库 fail-open 同一纪律）。

**注意**：settings namespace 按名字全局唯一注册。若同进程内旧版插件曾注册过旧 key，
新版注册新 key 不冲突；迁移读旧 key 用 document API（`ctx.settings.get`），不需要注册。

**首次发布说明**：升级到本版后首次加载插件时自动迁移；无需用户手动操作。

## 路径回溯逻辑（改名的隐藏耦合点）

三处硬编码 `'plugins/prompt-master'` 段做 dist→preset 根回溯，必须与新目录名一致：

- `src/resources/resolve.ts:20`
- `src/styles/registry.ts:42`、`:47`
- `src/dialect/anima-vector.ts:54`

均已随代码替换同步；此类逻辑若再新增，搜索锚点应是 `'plugins/prompt-'` 前缀。
