## 12. 总体结论

整体骨架（规则数、profile id 体系、路由优先级、清洗链、检查表/五点/anima3 §1–§5 正文）与 PM 3.1.0 高保真对齐，expand / reverse / taxonomy / train / tagLineSanitize 五族达到逐字级一致。**需要跟进归化的项，按优先级**：

1. **高**：minimax assemble（X1/X3/X5）——尤其 maxTokens 768 vs 上游 ≥4096 会直接截断 H3 输出；user 侧缺创作需求/素材锚定块会使 full_reference 场景失去 grounding。
2. **高**：torii prompts.ts（T1/T2/T4）——PROMPTS_B 7/11 键被重写、3 键缺失、JSON 后缀丢失；若要对标上游结构化打标行为需回填官方模板。
3. **中**：expandMirror 非结构化分支（M1/M2）——pe_expand_descriptive/danbooru 镜像生成内容与上游不同；anima3 custom 字数档（A1）；resolveReverse 自定义分支的长度块顶替（V1）；descriptive/prose 字数表述（D1）。
4. **低**：8 个 expand 内置 profile 的撞名语义（R1，需明确 legacy 映射策略）；comfyui.ts `pose/orion` typo（C1）；各处 description/守卫文案截短；labelUi 丢失（E1）。
